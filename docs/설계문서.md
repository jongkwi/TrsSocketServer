## 1. 시스템 개요
콜센터 사이트 **감시·알람 중계 서버** (Windows MFC 다이얼로그 앱, 트레이 상주).

| 인터페이스 | 포트 | 역할 |
|---|---|---|
| IPCS 클라이언트 | TCP 6321 | 라이선스(실행 허가) 체크 → `Run`/`Close` |
| 알람 뷰어 클라이언트 | TCP 6770 | heartbeat 응답, 장애 알람 푸시 |
| 사이트 감시 에이전트 | UDP 5363 | 장애/복구 이벤트 수신 → ACK echo |
| 5초 타이머 | - | LINK_CHECK 21분 미수신 사이트 장애 판정 |

알림 채널: 6770 푸시, 웹푸시(HTTP POST), 알림톡(PostgreSQL 큐 INSERT), 이메일(HTTP POST), IVR SMS(`SDK_SMS_SEND`).

## 3. 핵심 흐름
1. **시작**: `InitInstance` → 알림 스레드 → `DoModal` → `OnInitDialog` 타이머 등록 → 1초 후 DB 3개 연결 → 제외시간 로드 → 소켓 3개 생성 → `cc_update_time` 초기화
2. **6321**: STX/ETX 재조립 → `TTT?data IP:x` 파싱 → `IPCS_LOG` INSERT → `lic_access_list`(peer IP) count → raw `Run`/`Close`
3. **UDP**: 0xFF 분리 → `SITE_SMS_USER` 수신자 → `CallCenter_Link` 검증/신규 등록 → nType별 메시지 → ACK → 6770 푸시 + 웹푸시 + (제외시간 아니면) 알림톡 + (일부) 이메일
4. **링크 감시**: 5초마다 `cc_update_time <= now-21분` → 단절 알림 + `cc_link_error='Y'`; LINK_CHECK(100) 수신 시 복구

## 4. 설정·외부 의존
- `TRSSocket.ini`: 실제 사용 키는 `[LINK_SERVER] SERVER_PORT` 1개(도달 불가 분기). `BLOCK_IP`, `USER_LIC`, `SERVER_IP` 미사용
- 하드코딩: 포트 3개, DSN/계정 3세트, 웹푸시·메일 URL, 알림톡 sender key·발신번호
- DB: MSSQL 2012 `NASA_License`(`DB/*.bak`), PostgreSQL 알림톡 큐, SMS DB(제품 불명)

## 5. 죽은 코드

## 6. Linux 포팅 방향
단일 스레드 epoll 루프(소켓+timerfd) + 알림 워커 1개, unixODBC, libcurl, iconv. CP949 유지 권고. 상세·결정 사항은 `docs/포팅영향분석.md`.
