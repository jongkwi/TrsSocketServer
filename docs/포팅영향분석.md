# TrsSocketServer Linux 포팅 영향 분석

> 작성일: 2026-10-13 / 기준: `Source/TrsSocketServer_Lic_VS2019_Atalk/`
> 전제: 기존 클라이언트(IPCS 6321, 알람 뷰어 6770, 감시 에이전트 UDP 5363) **무변경**. 프로토콜은 `docs/프로토콜명세.md`를 따른다.

## 1. 아키텍처 비교

| 항목 | 현재 (Windows/MFC) | Linux 대체안 |
|---|---|---|
| 실행 형태 | 모달 다이얼로그 + 트레이 상주 GUI | 데몬 (systemd 서비스), stdout/syslog |
| 이벤트 모델 | 윈도 메시지 루프. `CAsyncSocket` 콜백(OnAccept/OnReceive/OnClose)과 `WM_TIMER`가 **단일 UI 스레드**에서 직렬 실행 | 단일 스레드 `epoll`(또는 `poll`) 루프 + `timerfd`. 소켓 이벤트와 타이머를 같은 루프에서 직렬 처리하면 현재의 동시성 의미(락 없음)를 그대로 유지 |
| 알림 발송 | 별도 워커 스레드 1개 (HTTP POST) | `std::thread` 1개 + `std::mutex`/`condition_variable` 큐 |
| DB | ODBC 2.x (MFC 없이 순수 ODBC API) | unixODBC 그대로 사용 가능. 3.x API(`SQLAllocHandle`, `SQLSetConnectAttr`)로 정리 권고 |
| 설정 | 포트·DSN·URL·키 하드코딩, ini 1키 | 설정 파일(ini/yaml) + 환경변수(비밀) |
| 6321 응답 지연 | 명시적 제한 없음 | **5초 이내 응답 필수** — IPCS 클라이언트가 `select`/`SO_RCVTIMEO` 5초 후 종료 (`docs/reference/client_license_check.cpp`). DB INSERT+SELECT가 블로킹이므로 DB 지연 시 단일 스레드 루프 전체가 멈춤 → DB 타임아웃 설정 또는 DB 작업 분리 검토 |
| DNS | - | 클라이언트가 `lic.onpia.co.kr` / `lic2.onpia.co.kr`:6321 로 접속. Linux 서버 배포 시 이 이름이 가리키도록 해야 함 |

**권장 구조**: 비즈니스 로직(`ServerProc`, `ServerUdpProc`, `OnCheckLinkData`, 알림 조립)은 플랫폼 독립 C++로 분리하고, 소켓/타이머/HTTP/DB를 인터페이스 뒤로 넣는다. 로직 함수의 입력(payload, peer IP, 현재 시각)과 출력(응답 바이트, DB 문장, 알림 요청)을 그대로 보존하면 프로토콜 호환성이 유지된다.

## 5. 인코딩 전략 (결정 필요)

| 선택지 | 내용 | 장단점 |
|---|---|---|
| A. CP949 유지 (권고) | 소스는 UTF-8로 변환하되 런타임 문자열(클라이언트 송수신, 알림 문구, DB 저장)은 CP949 유지. 한글 리터럴은 빌드 시 `-fexec-charset=cp949` 또는 런타임 iconv | 클라이언트·DB·알림 서버 모두 무변경. `Hangul_StrCut` 그대로 동작 |
| B. UTF-8 전환 | 내부 UTF-8, 소켓 경계에서 iconv | 6770 푸시 메시지가 UTF-8이 되어 **알람 뷰어 클라이언트 수정 필요** → 전제 위반. DB 컬럼 인코딩도 변경 |

A 선택 시 주의: `Hangul_StrCut` 2바이트 규칙, 알림톡 1024바이트·SMS 80바이트 제한, `URLEncode`의 CP949→UTF-8 변환은 그대로 iconv로 재현.

### 8.1 추가 필요 정보 (구성 착수 전)
1. **PostgreSQL 스키마**: `NASA_License` 운영 DDL은 확보(`docs/DB스키마.md` §2, PG 변환 §6). 남은 것: (a) **`lic_access_list` 부재** → 배포 exe 버전 확인 후 6321 허용 판정 기준 결정, (b) `NASA_License` 19개 테이블 중 OnAlarm 웹·NcLicense 공용 13개를 함께 이관할지(이중 운영 시 동기화 문제), (c) `"MTS_ATALK_MSG"` DDL(PG 203.239.159.134:39999 미접속)
2. **알림톡 큐 에이전트(MTS)**: `MTS_ATALK_MSG`를 읽는 프로세스의 위치와 `TRAN_TYPE=5`, `TRAN_STATUS='1'`의 의미, 템플릿 코드 30종이 카카오 등록 템플릿과 어떻게 매핑되는지(USER_MSG의 빈 템플릿 코드 허용 여부)
3. **빌드·배포 환경**: 대상 배포판과 GCC 버전, unixODBC/psqlODBC 버전, libcurl 사용 가능 여부(웹푸시·메일), systemd 사용 여부, 실행 계정과 설치 경로(onmw처럼 `bin/cfg/log` 구조)
4. **DNS 전환**: 운영 2대 확인됨 — `lic`=203.239.190.44(클라이언트 접속 0건, 로컬 MSSQL 34333 로그인 실패 추정), `lic2`=203.239.190.7(실운영, 로컬 MSSQL 1433 + 외부 PG 203.239.159.134:39999). 상세 `docs/DB스키마.md` §1.4. Linux 서버로 전환하는 시점. Windows 서버와 병행 운영(동일 DB 공유) 기간이 있는지 — 병행이면 `OnCheckLinkData`의 `cc_update_time`·`cc_link_error` 갱신이 양쪽에서 겹치므로 한쪽만 활성화해야 함
5. **알람 뷰어 클라이언트(TCP 6770)** 소스 또는 제품명: heartbeat `'3'` 주기와 푸시 수신 처리 확인용 (아직 소스 미확인)
6. **nType 14(USER_MSG), 200/201(IVR GPS/NORMAL)** 송신자: OnDemon·ncbk 모두 보내지 않음. 사용 중인 송신자가 없으면 유지만 하고 검증 범위에서 제외 가능
